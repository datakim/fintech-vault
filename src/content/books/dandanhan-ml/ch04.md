이 장의 실습 문제(4.3~4.10)는 모두 Python(numpy, pandas)으로 직접 구현해 실행한 결과를 실었습니다. 수박 데이터 세트는 책의 표 4.1~4.4를 그대로 옮겼고, 4.3에서 만든 공통 코드(`wm.py`, `tree.py`)를 뒤의 문제에서 다시 씁니다.

## 문제 4.1

> 충돌되는 데이터(conflicting data)(즉, 특성 벡터가 완전히 같지만 레이블은 다른)를 포함하지 않는 훈련 세트에 대해, 훈련 세트와 일치(훈련 오차가 0인)하는 의사결정 트리가 반드시 존재한다는 사실을 증명하라.

**풀이**

그림 4.2의 TreeGenerate가 (분할 속성을 어떤 기준으로 고르든) 항상 훈련 오차 0인 트리를 만든다는 것을 보이면 됩니다. 먼저 속성이 모두 이산 속성인 경우를 증명하고, 연속 속성은 뒤에서 덧붙입니다.

**Step 1. 경로 위의 샘플은 사용한 속성 값을 공유합니다.**

어떤 노드에 도달한 샘플 집합을 $D'$, 남은 속성 집합을 $A'$라고 하겠습니다. 루트에서 이 노드까지 오는 동안 쓰인 속성 $a \in A \setminus A'$마다 "$a = a^v$"인 가지를 따라 내려왔으므로, $D'$의 모든 샘플은 $A \setminus A'$의 각 속성에서 같은 값을 가집니다.

**Step 2. 리프가 만들어지는 세 경우를 모두 확인합니다.**

그림 4.2에서 리프는 세 곳에서만 만들어집니다.

1. 2~3행: $D'$의 샘플이 모두 같은 클래스 $C$에 속합니다. 리프의 레이블이 $C$이므로 이 리프에 도달한 훈련 샘플은 하나도 틀리지 않습니다.
2. 5~6행: $A' = \varnothing$이거나, $D'$의 샘플이 $A'$의 모든 속성에서 같은 값을 가집니다. 어느 쪽이든 Step 1과 합치면 $D'$의 샘플은 **모든 속성** $A$에서 같은 값을 가집니다. 즉 특성 벡터가 완전히 같습니다. 충돌되는 데이터가 없으므로 이들의 레이블도 모두 같고, 다수 클래스를 레이블로 붙이면 오차는 0입니다. (사실 이 경우는 이미 1번 조건에 걸리므로 5행까지 오지 않습니다.)
3. 11~12행: $D_v$가 공집합입니다. 이 리프에는 훈련 샘플이 하나도 도달하지 않으므로 훈련 오차에 영향을 주지 않습니다.

**Step 3. 알고리즘은 반드시 끝납니다.**

이산 속성은 한 번 쓰이면 $A$에서 제거되므로(14행의 $A \setminus \{a_*\}$) 경로 길이는 속성 수 $d$를 넘지 않습니다. 따라서 트리는 유한합니다.

**Step 4. 결론**

훈련 샘플 각각은 정확히 하나의 리프에 도달하고(각 노드에서 샘플 집합이 가지별로 분할되므로), 모든 리프에서 오차가 0입니다. 따라서 이 트리의 훈련 오차는 0입니다.

**연속 속성이 있는 경우**

4.4.1절처럼 연속 속성을 이분법으로 다루면 같은 속성을 여러 번 쓸 수 있으므로 Step 3의 논리가 그대로 통하지 않습니다. 대신 다음처럼 보입니다. 레이블이 섞인 노드에는 레이블이 다른 두 샘플이 있고, 충돌 데이터가 없으므로 두 샘플의 특성 벡터는 어떤 속성에서 다릅니다. 따라서 "모든 샘플이 모든 속성에서 같은 값"인 상황은 생기지 않고, 분할이 항상 가능합니다. 또 연속 속성의 후보 분할점(식 4.7)은 서로 다른 두 값의 중앙점이므로 분할 후 두 자식은 모두 비어 있지 않고, 각 자식의 샘플 수는 부모보다 엄격히 작습니다. 샘플 수는 자연수이므로 경로마다 유한 번 안에 순수한 노드(1번 경우)에 도달합니다. 따라서 이 경우에도 훈련 오차 0인 트리가 존재합니다. ∎

## 문제 4.2

> 최소 훈련 오차를 사용하여 의사결정 트리 분할의 기준으로 삼을 때 빠질 수 있는 함정에 대해 분석하라.

**풀이**

"분할 후 훈련 오차(각 가지에서 다수 클래스로 예측할 때 틀리는 개수)가 가장 작은 속성을 고른다"는 기준에는 두 가지 큰 함정이 있습니다.

**함정 1. 순도 변화에 둔감해서 속성을 구별하지 못하고, 성급하게 멈춥니다.**

훈련 오차는 각 가지의 다수 클래스가 바뀔 때만 줄어듭니다. 가지가 더 순수해져도 다수 클래스가 그대로면 오차는 변하지 않습니다. 수박 데이터 세트 2.0(표 4.1)으로 직접 비교하면 다음과 같습니다(`p42.py`, 아래 코드는 4.3의 `wm.py`, `tree.py`를 사용).

| 노드 | 속성 | 분할 후 훈련 오차 | 정보 이득 |
|------|------|------------------|-----------|
| 루트(17개, 분할 전 오차 8) | 색깔 | 6 | 0.108 |
| | 꼭지 모양 | 6 | 0.143 |
| | 소리 | 6 | 0.141 |
| | 줄무늬 | 3 | 0.381 |
| | 배꼽 모양 | 5 | 0.289 |
| | 감촉 | 8 | 0.001 |
| 줄무늬=선명함(9개, 분할 전 오차 2) | 색깔 | 2 | 0.043 |
| | 꼭지 모양 | 1 | 0.458 |
| | 소리 | 1 | 0.331 |
| | 배꼽 모양 | 1 | 0.458 |
| | 감촉 | 1 | 0.458 |

루트에서 색깔, 꼭지 모양, 소리는 훈련 오차로는 모두 6으로 같지만 정보 이득은 서로 다릅니다. 두 번째 노드에서도 네 속성이 오차 1로 동점인데, 정보 이득은 소리(0.331)가 다른 셋(0.458)보다 확실히 나쁘다고 알려 줍니다. 색깔은 순도를 조금 올리지만(이득 0.043) 오차는 전혀 줄이지 못합니다.

이 둔감함은 구조적인 문제입니다. 클래스 비율 $p$에 대한 오차 $\min(p, 1-p)$는 구간별 선형이라 엄격한 오목 함수가 아니고, 엔트로피나 지니값은 엄격한 오목 함수입니다. 예를 들어 (양성 400, 음성 400)인 노드를 A: (300, 100)+(100, 300)으로 나누든 B: (200, 400)+(200, 0)으로 나누든 훈련 오차는 둘 다 200입니다. 하지만 B는 순수한 노드를 하나 만들어 이후 분할이 훨씬 쉬워지고, 엔트로피도 B를 선호합니다(가중 엔트로피 A: 0.811, B: 0.689).

더 심각한 경우는 XOR 같은 구조입니다. 레이블이 $y = a_1 \oplus a_2$이면 $a_1$이나 $a_2$ 어느 쪽으로 먼저 나눠도 각 가지가 여전히 반반이라 오차가 전혀 줄지 않습니다. "오차가 줄지 않으면 멈춘다"는 규칙과 함께 쓰면 두 번만 나누면 완벽해지는 문제에서 루트부터 멈춰 버립니다.

**함정 2. 훈련 오차를 끝까지 줄이면 과적합합니다.**

훈련 오차는 일반화 오차의 낙관적인 추정치입니다(2장). 문제 4.1에서 보았듯 충돌 데이터만 없으면 훈련 오차 0인 트리는 언제나 존재하므로, 이 기준은 노이즈까지 외우는 깊은 트리로 우리를 이끕니다. 극단적인 예로 4.2.2절의 '번호' 속성을 후보에 넣으면 한 번의 분할로 훈련 오차가 0이 되므로 이 기준에서는 항상 최적입니다. 게다가 훈련 오차가 0이 되는 분할들은 모두 동점이라, 그중 더 단순한 분할을 고를 근거도 주지 못합니다.

**정리하면**, 분할 선택에는 순도 변화에 민감한(엄격히 오목한) 정보 이득, 이득율, 지니계수를 쓰고, 일반화 성능은 훈련 오차가 아니라 검증 세트를 이용한 가지치기(4.3절)로 따로 관리하는 것이 바람직합니다.

```python
import numpy as np
from collections import Counter
from wm import df20, LABEL
from tree import ent, score

def errors(y):                                   # 다수 클래스로 예측할 때 틀리는 개수
    return len(y) - max(Counter(y).values())

def subset_report(df, name):
    y = df[LABEL].to_numpy()
    print(f"{name}: 분할 전 오차 {errors(y)}/{len(y)}")
    for a in df.columns.drop(LABEL):
        x = df[a].to_numpy()
        e = sum(errors(y[x == v]) for v in np.unique(x))
        print(f"  {a:6s} 분할 후 오차 {e}/{len(y)}  정보 이득 {score(x, y, ent):.3f}")

subset_report(df20, "루트(17개)")
subset_report(df20[df20["줄무늬"] == "선명함"], "줄무늬=선명함(9개)")
```

```python
# tree.py
import numpy as np
from collections import Counter

def ent(y):                                    # 식 4.1
    p = np.array(list(Counter(y).values())) / len(y)
    return -(p * np.log2(p)).sum()

def gini(y):                                   # 식 4.5
    p = np.array(list(Counter(y).values())) / len(y)
    return 1 - (p ** 2).sum()

def majority(y):                               # 동점이면 '예'
    c = Counter(y)
    return max(c, key=lambda k: (c[k], k == "예"))

def score(x, y, imp, t=None):
    """분할 후 순도 개선량: 정보 이득(식 4.2, 4.8) 또는 -Gini_index(식 4.6)"""
    parts = [x == v for v in np.unique(x)] if t is None else [x <= t, x > t]
    s = sum(m.mean() * imp(y[m]) for m in parts)
    return imp(y) - s if imp is ent else -s

def best_split(x, y, imp):
    if x.dtype.kind != "f":                    # 이산 속성
        return score(x, y, imp), None
    xs = np.unique(x)
    best = (-np.inf, None)
    for t in (xs[:-1] + xs[1:]) / 2:           # 식 4.7의 후보 분할점
        s = score(x, y, imp, t)
        if s > best[0] + 1e-12:
            best = (s, t)
    return best

    best = (-np.inf, None, None)
    for a in A:                                # 동점이면 A에서 앞에 있는 속성
        s, t = best_split(X[a].to_numpy(), y, imp)
        if s > best[0] + 1e-12:
            best = (s, a, t)
    return best[1], best[2]

def tree_generate(X, y, A, values, imp=ent):
    """그림 4.2. 리프는 클래스 문자열, 내부 노드는 (속성, 분할점, {가지: 하위 트리})"""
    if len(set(y)) == 1:                                        # 2~4행
        return y[0]
    if not A or all(X[a].nunique() == 1 for a in A):            # 5~7행
        return majority(y)
    a, t = choose(X, y, A, imp)                                 # 8행
    x = X[a].to_numpy()
    if t is None:                                               # 이산: 모든 값으로 가지
        branches = {v: x == v for v in values[a]}
        A = [b for b in A if b != a]
    else:                                                       # 연속: 이분법, 속성 유지
        branches = {"예": x <= t, "아니오": x > t}
    children = {}
    for v, m in branches.items():                               # 9~16행
        children[v] = (majority(y) if not m.any()               # 11~12행
                       else tree_generate(X[m], y[m], A, values, imp))
    return (a, t, children)
```

## 문제 4.4

> 지니계수에 기반하여 분할 선택을 진행하는 의사결정 트리 알고리즘에 대한 코드를 작성하고, 표 4.2의 데이터를 사용해 사전 가지치기, 사후 가지치기 의사결정 트리를 만들고, 가지치기를 하지 않은 의사결정 트리와 비교해 보아라.

**풀이**

4.3의 `tree_generate`에 `imp=gini`를 넘기면 식 4.6의 Gini_index가 가장 작은 속성을 고르는 CART식 분할이 됩니다(코드에서는 $-\text{Gini\_index}$를 최대화). 여기에 4.3절의 두 가지치기를 붙입니다.

- **사전 가지치기**: 노드를 나누기 전에, 그 노드에 도달하는 검정 샘플의 정확도를 "분할하지 않고 다수 클래스 리프로 둘 때"와 "한 번 분할해서 각 가지를 다수 클래스 리프로 둘 때" 비교해, 분할 후가 엄격히 클 때만 나눕니다.
- **사후 가지치기**: 완성된 트리를 아래에서 위로 훑으면서, 하위 트리를 리프로 바꿨을 때 검정 정확도가 엄격히 올라가면 잘라냅니다. 책(102쪽)처럼 정확도가 같으면 자르지 않습니다.

한 노드의 결정은 그 노드에 도달하는 검정 샘플에만 영향을 주므로, 전체 검정 정확도를 비교하는 것과 노드에 도달한 검정 샘플만 비교하는 것은 같은 결과를 줍니다. 코드는 후자로 구현했습니다.

```python
import numpy as np
from wm import df20, LABEL, TRAIN, VAL
from tree import gini, majority, choose, score, tree_generate, show, predict

def pre_generate(X, y, Xv, yv, A, values, imp=gini):
    """사전 가지치기: 분할 후 검정 정확도가 올라갈 때만 분할한다(이산 속성)."""
    lab = majority(y)
    if len(set(y)) == 1 or not A or all(X[a].nunique() == 1 for a in A):
        return lab
    a, _ = choose(X, y, A, imp)
    x, xv = X[a].to_numpy(), Xv[a].to_numpy()
    before = (yv == lab).sum()
    after = sum((yv[xv == v] == (majority(y[x == v]) if (x == v).any() else lab)).sum()
                for v in values[a])
    print(f"  노드 {list(X.index)}: '{a}' 분할 전 {before}/{len(yv)}, 분할 후 {after}/{len(yv)}")
    if after <= before:
        return lab
    A2 = [b for b in A if b != a]
    return (a, None, {v: lab if not (x == v).any() else
                      pre_generate(X[x == v], y[x == v], Xv[xv == v], yv[xv == v], A2, values, imp)
                      for v in values[a]})

def post_prune(node, X, y, Xv, yv):
    """사후 가지치기: 아래에서 위로, 리프로 바꿔서 검정 정확도가 올라가면 자른다."""
    if isinstance(node, str):
        return node
    a, t, ch = node
    x, xv = X[a].to_numpy(), Xv[a].to_numpy()
    node = (a, t, {v: post_prune(sub, X[x == v], y[x == v], Xv[xv == v], yv[xv == v])
                   for v, sub in ch.items()})
    keep = sum(predict(node, r) == l for (_, r), l in zip(Xv.iterrows(), yv))
    cut = (yv == majority(y)).sum()
    print(f"  노드 '{a}' {list(X.index)}: 유지 {keep}/{len(yv)}, 리프로 {cut}/{len(yv)}")
    return majority(y) if cut > keep else node

def acc(tree, X, y):
    return np.mean([predict(tree, r) == l for (_, r), l in zip(X.iterrows(), y)])

A = ["배꼽 모양", "색깔", "꼭지 모양", "소리", "줄무늬", "감촉"]   # 동점 시 책과 같은 선택
tr, va = df20.loc[TRAIN], df20.loc[VAL]
X, y, Xv, yv = tr[A], tr[LABEL].to_numpy(), va[A], va[LABEL].to_numpy()
values = {a: list(dict.fromkeys(df20[a])) for a in A}
for a in A:
    print(f"Gini_index(D, {a}) = {-score(X[a].to_numpy(), y, gini):.3f}")
full = tree_generate(X, y, A, values, gini)
print("[가지치기 없음] 검정 정확도", acc(full, Xv, yv)); print(show(full))
print("[사전 가지치기]"); pre = pre_generate(X, y, Xv, yv, A, values)
print("검정 정확도", acc(pre, Xv, yv)); print(show(pre))
print("[사후 가지치기]"); post = post_prune(full, X, y, Xv, yv)
print("검정 정확도", acc(post, Xv, yv)); print(show(post))
```

## 문제 4.5

> 로지스틱 회귀에 기반하여 분할 선택을 진행하는 의사결정 트리 알고리즘에 대한 코드를 작성하고, 표 4.3의 데이터를 사용해 의사결정 트리를 생성하라.

**풀이**

문제의 의도를 "각 노드에서 그 노드의 샘플로 로지스틱 회귀(3.3절)를 학습하고, 로지스틱 회귀가 '예'로 예측한 샘플과 '아니오'로 예측한 샘플로 노드를 둘로 나눈다"로 해석했습니다. 각 비리프 노드가 선형 분류기 $\boldsymbol{w}^{\mathrm{T}}\boldsymbol{x} + b \ge 0$으로 테스트를 하므로, 4.5절의 다변량 의사결정 트리의 한 종류가 됩니다. (속성 하나씩 로지스틱 회귀를 학습해 가장 잘 맞는 속성을 고르는 단변량 해석도 가능하지만, 그러면 정보 이득 대신 다른 점수를 쓰는 것 외에 4.3과 큰 차이가 없습니다.)

구현 세부 사항은 다음과 같습니다.

- 이산 속성은 원-핫 인코딩(값마다 0/1 열)하고, 밀도와 당도는 그대로 씁니다. 입력은 모두 19차원입니다.
- 샘플 17개에 차원이 19라 훈련 데이터가 선형 분리 가능하므로, 그대로 최대 우도를 구하면 $\boldsymbol{w}$가 발산합니다. 그래서 $\frac{\lambda}{2}\lVert\boldsymbol{w}\rVert^2$ 벌점(절편 제외)을 더해 뉴턴법(식 3.29의 갱신식)으로 풉니다.
- 노드가 순수하거나, 로지스틱 회귀가 모든 샘플을 한쪽으로만 예측해 분할이 생기지 않으면 리프로 둡니다.

```python
import numpy as np, pandas as pd
from wm import df30, LABEL

def fit_logistic(X, y, lam=0.1, iters=50):
    """L2 정규화 로지스틱 회귀를 뉴턴법으로 푼다. y ∈ {0,1}, 절편에는 벌점을 주지 않는다."""
    Xh = np.hstack([X, np.ones((len(X), 1))])
    beta = np.zeros(Xh.shape[1])
    R = lam * np.eye(len(beta)); R[-1, -1] = 0
    for _ in range(iters):
        p = 1 / (1 + np.exp(-Xh @ beta))
        grad = Xh.T @ (p - y) + R @ beta
        H = Xh.T @ (Xh * (p * (1 - p))[:, None]) + R
        beta -= np.linalg.solve(H + 1e-9 * np.eye(len(beta)), grad)
    return beta

def lr_tree(X, y, ids, lam, depth=0, max_depth=5):
    lab = int(y.mean() >= 0.5)                          # 다수 클래스(동점이면 1 = 예)
    if y.min() == y.max() or depth == max_depth:
        return (lab, ids)
    beta = fit_logistic(X, y, lam)
    r = np.hstack([X, np.ones((len(X), 1))]) @ beta >= 0  # 로지스틱 회귀가 '예'로 본 쪽
    if r.all() or (~r).all():                            # 둘로 나뉘지 않으면 리프
        return (lab, ids)
    return (beta, ids, lr_tree(X[r], y[r], ids[r], lam, depth + 1, max_depth),
                       lr_tree(X[~r], y[~r], ids[~r], lam, depth + 1, max_depth))

def show(node, names, ind=0, k=3):
    if len(node) == 2:
        return " " * ind + f"→ {'예' if node[0] else '아니오'} {node[1].tolist()}\n"
    beta, ids, r, l = node
    top = np.argsort(-np.abs(beta[:-1]))[:k]             # 계수 절댓값이 큰 항 k개
    expr = " ".join(f"{beta[i]:+.2f}·[{names[i]}]" for i in top)
    return (" " * ind + f"- {expr} + … ≥ 0 ?\n"
            + " " * ind + "  예:\n" + show(r, names, ind + 4, k)
            + " " * ind + "  아니오:\n" + show(l, names, ind + 4, k))

D = pd.get_dummies(df30.drop(columns=LABEL), dtype=float)  # 이산 속성은 원-핫 인코딩
X, names = D.to_numpy(), list(D.columns)
y = (df30[LABEL] == "예").to_numpy().astype(int)
for lam in [0.1, 1.0]:
    print(f"λ = {lam}"); print(show(lr_tree(X, y, df30.index.to_numpy(), lam), names))
```

- 단변량 트리(그림 4.8)는 비리프 노드 3개로 같은 일을 하지만 노드마다 속성 하나만 보므로 해석이 쉽습니다. 로지스틱 회귀 트리는 노드 하나가 더 많은 일을 하는 대신, 노드의 판단 근거가 19개 계수의 조합이라 해석력이 떨어집니다.

## 문제 4.6

**풀이**

**실험 설계**

  - 정보 엔트로피와 지니계수는 4.3의 연속값 이분법을 그대로 쓰되, 속도를 위해 분할점 탐색을 누적 합으로 벡터화했습니다.

## 문제 4.7

> 그림 4.2는 재귀 알고리즘(recursive)이다. 만약 매우 큰 데이터를 만나게 된다면 의사결정 트리의 층수가 매우 깊어져, 재귀 방법을 사용하면 '스택(stack)'이 넘치기 쉽다. '선입선처리(First In First Out, FIFO)' 데이터 구조를 사용하고 파라미터 MaxDepth로 트리의 최대 깊이를 제어할 수 있게 만들면서, 그림 4.2와 같은 값을 가지지만 재귀적 의사결정 트리 생성 알고리즘을 사용하지 않는 알고리즘을 작성해 보아라.

**풀이**

재귀 호출이 하던 일은 "아직 처리하지 않은 노드(와 그 노드의 샘플, 남은 속성)"를 기억해 두는 것입니다. 이것을 콜 스택 대신 직접 만든 큐에 넣으면 재귀가 필요 없습니다. 큐의 원소는 (부모 노드의 가지 사전, 가지 이름, $D$, $A$, 깊이)이고, 원소를 꺼내 처리한 결과(리프 또는 새 내부 노드)를 부모의 해당 가지에 써 넣습니다. 깊이가 MaxDepth에 도달한 노드는 더 나누지 않고 다수 클래스 리프로 만듭니다.

**의사 코드**

```
입력: 훈련 세트 D, 속성 집합 A, 최대 깊이 MaxDepth
1: root 자리를 만들고, 큐 Q ← [(root 자리, D, A, 깊이 0)]
2: while Q가 비어 있지 않으면 do
3:     (자리, D', A', d) ← Q에서 맨 앞 원소를 꺼낸다
4:     if D'의 샘플이 모두 클래스 C then 자리 ← 레이블 C인 리프; continue
5:     if A' = ∅ 또는 D'가 A'에서 모두 같은 값 또는 d ≥ MaxDepth then
6:         자리 ← D'의 다수 클래스 리프; continue
7:     A'에서 최적 분할 속성 a*를 선택하고, 자리 ← 내부 노드(a*)
8:     for a*의 각 값 a*^v do
9:         D_v ← D'에서 a* = a*^v인 샘플
10:        if D_v = ∅ then 가지 a*^v ← D'의 다수 클래스 리프
11:        else Q의 맨 뒤에 (가지 a*^v 자리, D_v, A' \ {a*}, d + 1)을 넣는다
12: end while
출력: root를 루트로 하는 의사결정 트리
```

**구현** (4.3의 `tree.py` 사용)

```python
from collections import deque
import numpy as np
from tree import ent, majority, choose, tree_generate, show

def tree_generate_fifo(X, y, A, values, imp=ent, max_depth=np.inf):
    """그림 4.2를 재귀 없이: 할 일(노드)을 FIFO 큐에 넣고 하나씩 꺼내 처리한다."""
    holder = {}                                          # 루트를 담을 자리
    Q = deque([(holder, "root", X, y, A, 0)])            # (부모의 가지 사전, 가지 이름, D, y, A, 깊이)
    while Q:
        parent, key, X, y, A, d = Q.popleft()            # 먼저 들어온 것부터
        if len(set(y)) == 1:                             # 2~4행
            parent[key] = y[0]; continue
        if not A or all(X[a].nunique() == 1 for a in A) or d >= max_depth:   # 5~7행 + 깊이 제한
            parent[key] = majority(y); continue
        a, t = choose(X, y, A, imp)                      # 8행
        x = X[a].to_numpy()
        if t is None:
            branches, A2 = {v: x == v for v in values[a]}, [b for b in A if b != a]
        else:
            branches, A2 = {"예": x <= t, "아니오": x > t}, A
        node = (a, t, {}); parent[key] = node
        for v, m in branches.items():                    # 9~16행: 재귀 호출 대신 큐에 넣는다
            if not m.any():
                node[2][v] = majority(y)
            else:
                Q.append((node[2], v, X[m], y[m], A2, d + 1))
    return holder["root"]
```

**검증과 실행 결과**

MaxDepth를 두지 않으면 수박 데이터 세트 2.0과 3.0 모두에서 4.3의 재귀 버전과 완전히 같은 트리(그림 4.4, 그림 4.8)가 나왔습니다(`tree_generate_fifo(...) == tree_generate(...)`가 `True`). 노드를 처리하는 순서만 다를 뿐, 각 노드에서 받는 $D$와 $A$가 같으므로 같은 결과가 나오는 것이 당연합니다.

수박 데이터 세트 2.0에서 MaxDepth를 주면 다음과 같습니다.

```
MaxDepth = 1
- 줄무늬 = 선명함 → 예
- 줄무늬 = 약간 흐림 → 아니오
- 줄무늬 = 흐림 → 아니오

MaxDepth = 2
- 줄무늬 = 선명함
  - 꼭지 모양 = 말림 → 예
  - 꼭지 모양 = 약간 말림 → 예
  - 꼭지 모양 = 곧음 → 아니오
- 줄무늬 = 약간 흐림
  - 감촉 = 단단함 → 아니오
  - 감촉 = 물렁함 → 예
- 줄무늬 = 흐림 → 아니오
```

'줄무늬 = 약간 흐림' 노드는 다수 클래스가 '아니오'(5개 중 4개)라서 MaxDepth = 1에서 '아니오' 리프가 되었습니다.

참고로 큐 대신 스택(`Q.pop()`)을 쓰면 같은 코드가 깊이 우선 순서로 노드를 처리합니다. 어느 쪽이든 명시적인 자료 구조는 힙 메모리에 있으므로 콜 스택이 넘치는 문제는 생기지 않습니다.

## 문제 4.8\* (심화)

> 깊이 우선 탐색(Depth-First Search, DFS) 과정을 너비 우선 탐색(Breadth-First Search, BFS) 과정으로 수정하고, 파라미터 MaxNode로 트리의 최대 노드 수를 제어하는 의사결정 트리 알고리즘을 문제 4.7을 기반으로 수정하여라. 문제 4.7의 알고리즘과 비교했을 때, 어떤 방법으로 구현한 의사결정 트리가 메모리 관리에 쉬운지 분석해 보아라.

**풀이**

먼저 짚어 둘 점이 있습니다. 그림 4.2의 재귀는 깊이 우선 탐색이지만, 4.7에서 요구한 FIFO 큐로 구현하면 그 자체가 이미 너비 우선 탐색이 됩니다. 그래서 이 문제를 "4.7의 비재귀 알고리즘을 너비 우선으로 두고, 깊이 제한(MaxDepth) 대신 노드 수 제한(MaxNode)으로 트리 크기를 제어하도록 바꾼 뒤, 깊이 우선(스택) + MaxDepth 방식과 메모리 측면에서 비교하라"는 뜻으로 해석했습니다.

**MaxNode 제어 방식**

노드 수는 루트 1개에서 시작합니다. 큐에서 꺼낸 노드를 $V$개 가지로 나누려 할 때 `현재 노드 수 + V > MaxNode`이면 나누지 않고 다수 클래스 리프로 만듭니다. 너비 우선이므로 얕은 노드부터 예산을 쓰게 되어, 예산이 떨어지면 트리가 비슷한 깊이에서 고르게 멈춥니다.

```python
from collections import deque
import numpy as np
from tree import ent, majority, choose, show, predict

def tree_generate_bfs(X, y, A, values, imp=ent, max_node=np.inf, lifo=False):
    """너비 우선(큐) 생성 + MaxNode. lifo=True면 같은 코드가 깊이 우선(스택)이 된다."""
    holder, n_nodes, peak = {}, 1, 1                     # 루트 1개로 시작
    Q = deque([(holder, "root", X, y, A)])
    while Q:
        parent, key, X, y, A = Q.pop() if lifo else Q.popleft()
        if len(set(y)) == 1:
            parent[key] = y[0]; continue
        if not A or all(X[a].nunique() == 1 for a in A):
            parent[key] = majority(y); continue
        a, t = choose(X, y, A, imp)
        x = X[a].to_numpy()
        if t is None:
            branches, A2 = {v: x == v for v in values[a]}, [b for b in A if b != a]
        else:
            branches, A2 = {"예": x <= t, "아니오": x > t}, A
        if n_nodes + len(branches) > max_node:           # 자식을 만들면 예산 초과 → 리프
            parent[key] = majority(y); continue
        n_nodes += len(branches)
        node = (a, t, {}); parent[key] = node
        for v, m in branches.items():
            if not m.any():
                node[2][v] = majority(y)
            else:
                Q.append((node[2], v, X[m], y[m], A2))
        peak = max(peak, len(Q))                         # 대기 중인 노드 수의 최댓값
    return holder["root"], n_nodes, peak
```

수박 데이터 세트 2.0에서 MaxNode = 4이면 루트와 자식 3개만 남아 4.7의 MaxDepth = 1과 같은 트리(노드 4개)가, MaxNode = 10이면 4.7의 MaxDepth = 2와 같은 트리(노드 9개)가 나옵니다. MaxNode = 10에서 노드 9개인 이유는, 다음 차례인 '꼭지 모양 = 약간 말림' 노드를 색깔로 나누면 자식 3개가 더해져 12개가 되어 예산을 넘기 때문입니다.

**메모리 비교 실험**

차이가 드러나도록 더 큰 데이터(digits, 1797개, 연속 속성 64개, 클래스 10개)로 돌려 보았습니다. "대기열 최대"는 아직 처리하지 않고 큐(또는 스택)에 쌓여 있던 노드 수의 최댓값입니다.

| 방식 | MaxNode | 노드 수 | 대기열 최대 | 깊이 | 훈련 정확도 |
|---|---|---|---|---|---|
| BFS(큐) | 제한 없음 | 295 | 66 | 11 | 1.000 |
| DFS(스택) | 제한 없음 | 295 | 9 | 11 | 1.000 |
| BFS(큐) | 63 | 63 | 32 | 5 | 0.846 |
| DFS(스택) | 63 | 63 | 9 | 9 | 0.524 |

**분석**

메모리는 두 부분으로 나눠 생각할 수 있습니다.

1. **완성된 트리 자체.** 저장 공간은 노드 수에 비례합니다. MaxNode를 쓰면 이 상한을 직접 정할 수 있습니다. 반면 MaxDepth로는 노드 수를 간접적으로만 제한할 수 있고, 가지 수가 $V$이면 최악의 경우 노드가 $O(V^{\text{MaxDepth}})$개까지 늘어나므로 메모리 사용량을 미리 알기 어렵습니다.
2. **생성 중의 대기열.** 너비 우선은 한 층 전체를 큐에 담으므로 대기열이 트리의 너비만큼 커지고(위 실험에서 66), 깊이 우선 스택은 대략 "깊이 × (가지 수 − 1)" 정도만 담습니다(9). 다만 대기열 원소가 가진 샘플 부분집합은 서로 겹치지 않으므로(한 층의 노드들은 $D$의 분할), 두 방식 모두 샘플을 담는 데 드는 메모리는 최대 $|D|$개 수준으로 같습니다. 차이는 원소 수에 비례하는 오버헤드 정도입니다.

메모리를 지배하는 것은 결국 트리 크기이므로, **MaxNode로 노드 수를 직접 묶는 너비 우선 방식이 메모리 관리에 더 쉽습니다.** 또 예산이 같을 때 너비 우선은 얕고 고른 트리를 만들어(깊이 5, 훈련 정확도 84.6%), 한쪽 가지만 깊게 파고들다 예산을 다 쓰는 깊이 우선(깊이 9, 52.4%)보다 같은 메모리로 더 쓸모 있는 트리를 얻었습니다. 반대로 생성 과정의 작업 메모리만 아주 작게 유지해야 한다면 깊이 우선 스택이 유리하지만, 그 경우에는 트리 크기를 따로 제어해야 합니다.

## 문제 4.9

> 4.4.2절에서 결측값에 대한 처리 메커니즘을 지니계수의 계산으로 확장하라.

**풀이**

4.4.2절의 기호를 그대로 씁니다. 속성 $a$에 결측값이 없는 샘플 집합을 $\tilde D$, 그중 $a$의 값이 $a^v$인 부분집합을 $\tilde D^v$, $k$번째 클래스인 부분집합을 $\tilde D_k$라 하고, 샘플 $\boldsymbol{x}$의 가중치를 $w_{\boldsymbol{x}}$라 합니다(루트에서 1). $\rho$, $\tilde p_k$, $\tilde r_v$는 식 4.9~4.11과 같습니다.

**Step 1. 가중치를 반영한 지니값**

식 4.5의 비율 $p_k$를 가중치 비율로 바꿉니다.

$$\mathrm{Gini}(\tilde D) = 1 - \sum_{k=1}^{|\mathcal{Y}|} \tilde p_k^2, \qquad \tilde p_k = \frac{\sum_{\boldsymbol{x} \in \tilde D_k} w_{\boldsymbol{x}}}{\sum_{\boldsymbol{x} \in \tilde D} w_{\boldsymbol{x}}}$$

각 가지 $\tilde D^v$의 지니값도 같은 방식으로, 그 가지 안의 가중치 비율 $\tilde p_k^v = \sum_{\boldsymbol{x} \in \tilde D^v_k} w_{\boldsymbol{x}} \big/ \sum_{\boldsymbol{x} \in \tilde D^v} w_{\boldsymbol{x}}$로 계산합니다.

**Step 2. 무결측 샘플에 대한 지니 지수**

식 4.6의 가중치 $|D^v|/|D|$를 $\tilde r_v$로 바꿉니다.

$$\mathrm{Gini\_index}(\tilde D, a) = \sum_{v=1}^{V} \tilde r_v\, \mathrm{Gini}(\tilde D^v)$$

**Step 3. 결측 비율 $\rho$의 반영**

식 4.12는 "무결측 샘플에서 얻은 순도 개선량에 $\rho$를 곱한다"는 구조입니다. 지니계수에서도 같은 구조를 유지하려면 **개선량**(지니 감소량)에 $\rho$를 곱해야 합니다.

$$\Delta\mathrm{Gini}(D, a) = \rho \times \left( \mathrm{Gini}(\tilde D) - \sum_{v=1}^{V} \tilde r_v\, \mathrm{Gini}(\tilde D^v) \right), \qquad a_* = \underset{a \in A}{\arg\max}\; \Delta\mathrm{Gini}(D, a)$$

여기서 흔히 하는 실수가 $\rho \times \mathrm{Gini\_index}(\tilde D, a)$를 최소화하는 것입니다. Gini_index는 작을수록 좋은 값이므로 $\rho < 1$을 곱하면 결측이 **많은** 속성일수록 오히려 유리해집니다. 정보 이득에서 $\rho$가 결측이 많은 속성에 불이익을 주던 것과 정반대 방향이므로, 위처럼 감소량에 곱해야 합니다. 결측이 없으면 $\rho = 1$이고 $\mathrm{Gini}(\tilde D)$는 모든 속성에 공통이므로, $\Delta\mathrm{Gini}$를 최대화하는 것은 원래의 식 4.6을 최소화하는 것과 같아집니다.

**Step 4. 샘플 분배**

분할 속성이 정해진 뒤의 처리는 4.4.2절과 똑같습니다. $a$ 값을 아는 샘플은 해당 가지로 가중치 $w_{\boldsymbol{x}}$를 유지한 채 보내고, 모르는 샘플은 모든 가지로 보내면서 가지 $v$에서의 가중치를 $\tilde r_v \cdot w_{\boldsymbol{x}}$로 조정합니다. 이 가중치가 하위 노드의 $\tilde p_k$, $\tilde r_v$, $\rho$ 계산에 그대로 쓰입니다.

**수박 데이터 세트 2.0α(표 4.4)로 확인**

위 식을 구현해 표 4.4의 루트에서 계산하면 다음과 같습니다. 같은 코드로 정보 이득도 계산해 책(109쪽)과 맞는지 함께 확인했습니다.

| 속성 | $\rho$ | 정보 이득 (식 4.12) | $\mathrm{Gini}(\tilde D)$ | $\sum_v \tilde r_v \mathrm{Gini}(\tilde D^v)$ | $\Delta\mathrm{Gini}$ |
|---|---|---|---|---|---|
| 색깔 | 14/17 = 0.824 | 0.252 | 0.490 | 0.333 | 0.129 |
| 꼭지 모양 | 15/17 = 0.882 | 0.171 | 0.498 | 0.390 | 0.095 |
| 소리 | 0.882 | 0.145 | 0.498 | 0.410 | 0.077 |
| 줄무늬 | 0.882 | 0.424 | 0.498 | 0.221 | 0.244 |
| 배꼽 모양 | 0.882 | 0.289 | 0.498 | 0.324 | 0.154 |
| 감촉 | 0.882 | 0.001 | 0.498 | 0.497 | 0.001 |

정보 이득은 감촉을 제외하고 책의 값과 같습니다. 감촉은 4.3에서 본 것처럼 표 4.4의 12번 감촉이 '단단함'으로 되어 있어 0.001이 나오고, '물렁함'으로 두면 책과 같은 0.006이 나옵니다(트리 결과는 어느 쪽이든 같습니다). 지니 감소량으로도 줄무늬가 0.244로 가장 커서 루트 분할은 같습니다.

```python
import numpy as np

def w_imp(y, w, crit):
    """가중치를 반영한 정보 엔트로피 / 지니값 (p̃_k 는 식 4.10처럼 가중치 비율)"""
    p = np.array([w[y == k].sum() for k in np.unique(y)]) / w.sum()
    p = p[p > 0]
    return -(p * np.log2(p)).sum() if crit == "ent" else 1 - (p ** 2).sum()

def w_score(x, y, w, crit):
    """ρ × [Imp(D̃) − Σ_v r̃_v Imp(D̃^v)]  (crit='gini'면 지니 감소량)"""
    ok = ~x.isna().to_numpy(); x = x.to_numpy()
    rho = w[ok].sum() / w.sum()                                   # 식 4.9
    xo, yo, wo = x[ok], y[ok], w[ok]
    after = sum(wo[xo == v].sum() / wo.sum() * w_imp(yo[xo == v], wo[xo == v], crit)
                for v in np.unique(xo))                           # r̃_v 는 식 4.11
    return rho * (w_imp(yo, wo, crit) - after)

def w_major(y, w):                                                # 동점이면 '예'
    return max(["예", "아니오"], key=lambda k: w[y == k].sum())

def gen(X, y, w, A, values, crit):
    lab = w_major(y, w)
    if len(np.unique(y)) == 1 or not A or all(X[a].dropna().nunique() <= 1 for a in A):
        return lab
    s = [w_score(X[a], y, w, crit) for a in A]
    a = A[int(np.argmax(np.round(s, 12)))]                        # 동점이면 앞 속성
    x = X[a].to_numpy(); ok = ~X[a].isna().to_numpy()
    ch = {}
    for v in values[a]:
        hit = ok & (x == v)
        if not hit.any():
            ch[v] = lab; continue
        r = w[hit].sum() / w[ok].sum()
        m = hit | ~ok                                             # 결측 샘플은 모든 가지로
        w2 = np.where(hit, w, w * r)[m]                           # 가중치 r̃_v · w_x
        ch[v] = gen(X[m], y[m], w2, [b for b in A if b != a], values, crit)
    return (a, ch)
```

(`X`는 표 4.4를 빈칸은 결측값으로 해서 읽은 데이터 프레임입니다. 트리를 출력하는 함수는 생략했습니다.)

**생성된 트리 비교**

정보 이득(`crit="ent"`)으로 만든 트리는 **그림 4.9와 완전히 같습니다.** 지니계수(`crit="gini"`)로 만든 트리는 '줄무늬 = 약간 흐림' 가지만 다릅니다.

    - 색깔 = 진녹색

## 문제 4.10

> 임의의 다중 변수 의사결정 트리를 만들고, 수박 데이터 세트 3.0에서 어떤 결과가 나오는지 확인해 보아라.

**풀이**

4.5에서 만든 로지스틱 회귀 트리도 다변량 의사결정 트리이므로, 여기서는 다른 선형 분류기를 노드에 넣어 봅니다. 두 가지를 구현했습니다.

1. **선형 판별분석(LDA) 노드**: 노드의 샘플로 3.4절의 선형 판별분석 방향 $\boldsymbol{w} = \mathbf{S}_w^{-1}(\boldsymbol{\mu}_0 - \boldsymbol{\mu}_1)$을 구하고, 샘플을 $\boldsymbol{w}^{\mathrm{T}}\boldsymbol{x}$로 사영한 1차원 값 위에서 정보 이득이 가장 큰 분할점을 고릅니다(식 4.7, 4.8을 사영값에 적용). 원-핫 인코딩한 이산 속성은 선형 종속이라 $\mathbf{S}_w$가 특이 행렬이 되므로 $10^{-3}\mathbf{I}$를 더했습니다.
2. **각도 탐색 노드**(속성 2개일 때만): 방향 $\boldsymbol{w} = (\cos\theta, \sin\theta)$를 0.5°씩 돌려 가며(360개) 각 방향에서 정보 이득이 가장 큰 분할점을 구하고, 전체에서 가장 좋은 사선 분할을 고릅니다. 분할 기준을 직접 최적화하는 방식이라 OC1 같은 알고리즘의 아이디어와 가깝습니다.

두 방법 모두 결정적이라 시드가 필요 없고, 노드가 순수해질 때까지 나눕니다.

```python
import numpy as np, pandas as pd
from wm import df30, LABEL
from tree import ent

def best_threshold(z, y):
    """사영값 z 위에서 정보 이득이 가장 큰 분할점 (식 4.7, 4.8)"""
    zs = np.unique(z); best = (-1, None)
    for t in (zs[:-1] + zs[1:]) / 2:
        l = z <= t
        g = ent(y) - l.mean() * ent(y[l]) - (~l).mean() * ent(y[~l])
        if g > best[0] + 1e-12: best = (g, t)
    return best

def lda_split(X, y, reg=1e-3):
    """선형 판별분석(식 3.39)의 방향 w = S_w^{-1}(μ0 − μ1)로 사영한 뒤 분할점을 고른다."""
    X0, X1 = X[y == 0], X[y == 1]
    Sw = (X0 - X0.mean(0)).T @ (X0 - X0.mean(0)) + (X1 - X1.mean(0)).T @ (X1 - X1.mean(0))
    w = np.linalg.solve(Sw + reg * np.eye(X.shape[1]), X0.mean(0) - X1.mean(0))
    w /= np.linalg.norm(w)
    return w, best_threshold(X @ w, y)[1]

def angle_split(X, y, steps=360):
    """2차원 전용: 방향을 0.5°씩 돌려 가며 정보 이득이 가장 큰 사선 분할을 찾는다."""
    best = (-1, None, None)
    for th in np.arange(steps) * np.pi / steps:
        w = np.array([np.cos(th), np.sin(th)])
        g, t = best_threshold(X @ w, y)
        if g > best[0] + 1e-12: best = (g, w, t)
    return best[1], best[2]

def mv_tree(X, y, ids, split):
    if y.min() == y.max():
        return ("예" if y[0] else "아니오", ids)
    w, t = split(X, y)
    if t is None:                                          # 사영값이 모두 같으면 리프
        return ("예" if y.mean() >= 0.5 else "아니오", ids)
    l = X @ w <= t
    return (w, t, mv_tree(X[l], y[l], ids[l], split), mv_tree(X[~l], y[~l], ids[~l], split))

y = (df30[LABEL] == "예").to_numpy().astype(int); ids = df30.index.to_numpy()
Xa = df30[["밀도", "당도"]].to_numpy()                        # 연속 속성 두 개(= 3.0α)
D = pd.get_dummies(df30.drop(columns=LABEL), dtype=float)     # 3.0 전체: 이산 속성은 원-핫
# 출력 함수 show는 4.5와 같은 방식이라 생략
```
